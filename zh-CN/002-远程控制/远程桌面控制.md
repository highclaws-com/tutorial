# 远程桌面控制

**用途**：在目标主机上部署 Apache Guacamole，再由 Cloudflare 把它变成一个 HTTPS 网址。拿到网址、用户名和密码的人，在普通浏览器里就能看到并操作这台机器当前的物理桌面，也可以打开一个连到它的终端敲命令。

**读者**：执行部署的 AI Agent。命令可以直接复制执行。

**适用范围**：第 1 到 9 节以 Linux X11 桌面为例，这是唯一经过实际验证的路径。Windows 与 macOS 的差异集中在第 10 节，那一节未经验证。

## 0. 占位符

| 占位符 | 含义 |
|---|---|
| `<TARGET_HOST>` | 目标主机。本文不记录它的主机名，文中命令都在该主机上执行 |
| `<TARGET_USER>` | 目标主机上要登录的账号，终端连接用它 |
| `<TARGET_PASSWORD>` | 上面那个账号的密码 |
| `<ADMIN_PASSWORD>` | Guacamole 管理员密码，3.1 节生成 |
| `<VNC_PASSWORD>` | VNC 密码，3.1 节生成 |
| `<PUBLIC_URL>` | 公网入口网址，第 6 节取得 |

## 1. 前提

目标主机要有一个正在运行的 X11 图形会话，而不是 Wayland；要有 sudo、Docker 与 Docker Compose、cloudflared；还要有 sshd 在 22 端口上监听，第 5 节要用到它。确认 sshd 在跑，执行 `ss -tlnp | grep ':22'`。

Linux 上共享桌面必须走 VNC 而不是 RDP。要看到的是同一块物理屏上已经开着的窗口，而 Linux 的 RDP 服务会另起一个独立登录会话，看不到本机桌面。Windows 和 macOS 自带的能力不一样，见第 10 节。

## 2. 固定版本

必须使用下表的 tag，不要用 `latest`：

| 用途 | 镜像 | 已验证 digest |
|---|---|---|
| Web 界面 | `guacamole/guacamole:1.6.0` | `sha256:f344085e618bb05e22b964b0208dbd06d3468275bac70206f93805245e067b40` |
| 协议代理 | `guacamole/guacd:1.6.0` | `sha256:8974eaa9ba32f713daf311e7cc8cd7e4cdfba1edea39eed75524e78ef4b08f4f` |
| 数据库 | `postgres:18` | `sha256:a9abf4275f9e99bff8e6aed712b3b7dfec9cac1341bba01c1ffdfce9ff9fc34a` |

桌面和终端共用这三个镜像，没有别的组件要装。

## 3. 部署 Guacamole

全部操作都在 `~/services/guacamole` 目录里完成。这一节只把 Guacamole 本身跑起来，接下来两节分别接桌面和接终端，彼此独立。

### 3.1 建目录、生成凭据

```bash
mkdir -p ~/services/guacamole/{initdb,recordings,postgres-data}
cd ~/services/guacamole

printf 'POSTGRES_PASSWORD=%s\n' "$(openssl rand -base64 24 | tr -d '/+=' | head -c 28)" > .env
openssl rand -base64 18 | tr -d '/+=' | head -c 20 > guac-admin-password.txt
openssl rand -base64 12 | tr -d '/+=' | head -c 8 > vnc-plain.txt
x11vnc -storepasswd "$(cat vnc-plain.txt)" vnc.pass
chmod 600 .env guac-admin-password.txt vnc-plain.txt vnc.pass
```

宿主机还没装 x11vnc 的话先装上：Debian 和 Ubuntu 执行 `apt install -y x11vnc`，Arch 执行 `pacman -Sy --noconfirm x11vnc`。

### 3.2 生成数据库结构

这一步必须在数据库第一次启动之前做完，否则建出来的是空库。

```bash
docker run --rm guacamole/guacamole:1.6.0 /opt/guacamole/bin/initdb.sh --postgresql > initdb/001-guacamole.sql
```

### 3.3 compose.yaml

```yaml
name: guacamole
services:
  guacd:
    image: guacamole/guacd:1.6.0
    container_name: guacd
    restart: unless-stopped
    networks: [guacnet]
  postgres:
    image: postgres:18
    container_name: guac-postgres
    restart: unless-stopped
    environment:
      POSTGRES_DB: guacamole_db
      POSTGRES_USER: guacamole_user
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?set in .env}
    volumes:
      - ./postgres-data:/var/lib/postgresql
      - ./initdb:/docker-entrypoint-initdb.d:ro
    networks: [guacnet]
  guacamole:
    image: guacamole/guacamole:1.6.0
    container_name: guac-web
    restart: unless-stopped
    depends_on: [guacd, postgres]
    environment:
      GUACD_HOSTNAME: guacd
      GUACD_PORT: "4822"
      POSTGRESQL_HOSTNAME: postgres
      POSTGRESQL_PORT: "5432"
      POSTGRESQL_DATABASE: guacamole_db
      POSTGRESQL_USER: guacamole_user
      POSTGRESQL_PASSWORD: ${POSTGRES_PASSWORD:?set in .env}
      POSTGRESQL_AUTO_CREATE_ACCOUNT_SCHEMA: "false"
    ports:
      - "127.0.0.1:8080:8080"
    volumes:
      - ./recordings:/var/lib/guacamole/recordings
    networks: [guacnet]
networks:
  guacnet:
    driver: bridge
    ipam:
      config:
        - subnet: 172.30.0.0/24
```

有三处不要改。Web 只绑在 `127.0.0.1:8080`，这样只有本机的隧道访问得到，局域网碰不到。`guacd` 和 `postgres` 不映射任何宿主机端口。子网固定成 `172.30.0.0/24`，宿主机在这个网络里的地址就是 `172.30.0.1`，后面两节都要用到它。

### 3.4 启动

```bash
docker compose up -d
docker compose ps                       # guacd 应为 healthy
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/guacamole/   # 期望 200
```

### 3.5 取 API 令牌并换掉默认密码

Guacamole 的连接都通过它自己的 REST API 创建，不用改数据库，也不用点界面。API 基址是 `http://127.0.0.1:8080/guacamole/api`，数据源写作 `postgresql`，此后每个请求都要带上 `?token=<authToken>`。

先用 `POST /tokens` 取令牌，表单内容为 `username=guacadmin&password=guacadmin`。拿到以后立刻换掉默认密码，`PUT /session/data/postgresql/users/guacadmin/password`，请求体是 `{"oldPassword":"guacadmin","newPassword":"<ADMIN_PASSWORD>"}`。然后用新密码重新登录，确认旧密码已经登录不了。

下面两节建连接时，用的都是这里拿到的令牌。

## 4. 桌面连接

这一节把目标主机当前的物理桌面接进浏览器，做出两条东西：一条 Guacamole 里的 vnc 连接，和一个在宿主机上运行的 x11vnc。

### 4.1 建 VNC 连接

带上 3.5 节的令牌，向 `POST /session/data/postgresql/connections` 提交：

```json
{"parentIdentifier":"ROOT","name":"This Computer (Desktop)","protocol":"vnc",
 "parameters":{"hostname":"172.30.0.1","port":"5900","password":"<VNC_PASSWORD>","color-depth":"16"},
 "attributes":{}}
```

`hostname` 填 `172.30.0.1`，这是宿主机在 Docker 网关上的地址。Guacamole 的代理进程跑在容器里，填 `localhost` 只会指到容器自己。端口 5900 对应下一节要拉起的 x11vnc，密码是 3.1 节生成的 `<VNC_PASSWORD>`。

### 4.2 启动桌面共享

以图形会话所属用户的身份执行，不要用 root。

```bash
# -auth 指向该图形会话的 X 授权文件。在会话里执行时用 "$XAUTHORITY"；
# 从 SSH 进来时用 ls ~/.Xauthority /run/user/$UID/*/Xauthority /tmp/serverauth.* 2>/dev/null | head -1 找
AUTH=<可读的 X 授权文件路径>

systemd-run --user --unit=x11vnc-guac /usr/bin/x11vnc \
  -display :0 -auth "$AUTH" \
  -rfbauth ~/services/guacamole/vnc.pass -rfbport 5900 \
  -listen 172.30.0.1 -no6 -noipv6 -forever -shared \
  -scale 1/2 -xdamage -wait 20 -defer 20

ss -tlnp | grep 5900        # 应监听在 172.30.0.1
```

`-display` 填实际会话的 display 号，通常是 `:0`。后面几个参数直接决定画面流不流畅：

| 参数 | 作用 |
|---|---|
| `-listen 172.30.0.1` | 只对 Docker 内网开放，局域网和公网都连不到 |
| `-scale 1/2` | 服务端把画面缩到一半再发，像素量降到四分之一 |
| `-xdamage` | 只发画面上变化的区域。不要用 `-noxdamage` |
| `-wait 20 -defer 20` | 更新节流，两个都是默认值，写出来方便调 |

去掉 `-scale` 或者换成 `-noxdamage`，画面会明显卡顿并出现黑色方块。

### 4.3 关闭熄屏

不做这一步，桌面空闲一段时间后会黑掉，远程画面里就是一片全黑，很容易被当成故障。

```bash
export DISPLAY=:0
xset s off; xset s noblank; xset -dpms
echo 0 > /sys/class/graphics/fb0/blank    # 当前已经黑了的话用它唤醒
```

这是 X11 的运行时状态，桌面重新登录后会失效，需要重做一次。

## 5. 终端连接

这一节给浏览器加一个连到目标主机的终端，产物是一条 Guacamole 里的 ssh 连接。它和上一节完全独立，可以单独做。

### 5.1 建 SSH 连接

同样带上 3.5 节的令牌，接口也是 `POST /session/data/postgresql/connections`：

```json
{"parentIdentifier":"ROOT","name":"Terminal (SSH)","protocol":"ssh",
 "parameters":{"hostname":"172.30.0.1","port":"22","username":"<TARGET_USER>","password":"<TARGET_PASSWORD>"},
 "attributes":{}}
```

`hostname` 和桌面连接一样填 `172.30.0.1`。`username` 与 `password` 是目标主机上能登录的账号，本文写作 `<TARGET_USER>` 和 `<TARGET_PASSWORD>`。Guacamole 也支持用 `private-key` 参数改成密钥登录，用密码最简单，这里只说密码。

### 5.2 验证容器到宿主机 sshd 的通路

这条连接要求宿主机的 sshd 允许从 Docker 网段登录。可以先自测一下：

```bash
docker exec guac-web bash -c 'exec 3<>/dev/tcp/172.30.0.1/22; read -r -t 4 l <&3; echo "$l"'
```

能打印出 `SSH-2.0-OpenSSH_...` 就是通的。不通的话，检查宿主机 sshd 有没有在跑，以及防火墙有没有放行 Docker 网桥到 22 端口。

## 6. 暴露与交付

```bash
cd ~/services/guacamole
cloudflared tunnel --no-autoupdate --url http://127.0.0.1:8080 > cloudflared.log 2>&1 &
echo $! > cloudflared.pid
sleep 10
grep -oE 'https://[a-z0-9-]+\.trycloudflare\.com' cloudflared.log | tail -1
```

命令输出的域名后面接上 `/guacamole/`，就是入口网址，本文记作 `<PUBLIC_URL>`：

```
https://<输出的随机域名>.trycloudflare.com/guacamole/
```

用 `curl -s -o /dev/null -w '%{http_code}\n' <PUBLIC_URL>` 验证，期望返回 200。

交给使用者时，只需要三项：入口网址 `<PUBLIC_URL>`、用户名 `guacadmin`、密码 `cat ~/services/guacamole/guac-admin-password.txt` 的输出。另外要说清两件事：网址是临时的，隧道或机器重启后会变，届时重跑本节取新的；它直接显示目标主机的真实桌面，应当按机密对待，不要转发。

## 7. 完成判据

- 三个容器都在运行，`guacd` 显示 healthy
- 本机访问 `http://127.0.0.1:8080/guacamole/` 返回 200
- 默认密码 `guacadmin` 登录失败，新密码可以登录
- 连接列表里有一条 vnc 连接指向 `172.30.0.1:5900`，另有一条 ssh 连接指向 `172.30.0.1:22`
- 从公网入口登录后，能看到并操作目标主机的真实桌面
- 从公网入口登录后，打开终端能得到可用的 shell 提示符

## 8. 故障处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 入口 404 | 网址少了 `/guacamole/` | 补全路径 |
| 入口打不开 | 隧道进程结束或网址已变 | 重跑第 6 节取新网址 |
| 登录失败 | 还在用默认密码 | 读 `guac-admin-password.txt` |
| 桌面全黑 | 桌面被熄屏 | 执行 4.3 节 |
| 桌面显示锁屏 | 桌面本来就锁着 | 要在目标主机上解锁，远程绕不过去 |
| 报 VNC 不可达 | x11vnc 没在跑，或 `-auth` 路径过期 | 重跑 4.2 节，路径每次桌面登录后都会变 |
| 桌面卡、有黑块 | 缩放或色深设置丢了 | 核对 `-scale 1/2` 与 `color-depth=16` |
| 数据库连不上 | `.env` 和已初始化的库对不上 | 删掉 `postgres-data/`，重做 3.2 到 3.4 |
| 终端连不上 | sshd 没在跑，或防火墙拦住了 Docker 网桥到 22 | 按 5.2 节自测，再检查宿主机 sshd 与防火墙 |
| 终端报认证失败 | 账号密码不对，或该账号不允许密码登录 | 核对 `<TARGET_USER>` 与 `<TARGET_PASSWORD>`，并检查宿主机 sshd 的 `PasswordAuthentication` |

## 9. 重启后恢复

三个容器靠 `restart: unless-stopped` 自己会回来，两条连接存在数据库里，也不用重建。需要重新拉起的只有两样：4.2 节的 x11vnc，和第 6 节的隧道。

## 10. Windows 和 macOS 目标主机

本节未经实际验证，只是根据 Guacamole 官方文档和这两套系统自带的能力做的概括。本文唯一确证可用的，是第 1 到 9 节的 Linux 路径。

和 Linux 最大的区别是，Windows 和 macOS 都自带远程桌面服务，不需要像 Linux 那样另外装 x11vnc。Windows 自带 RDP，macOS 的屏幕共享本身就是 VNC 协议。所以 4.2 节整节可以跳过，只要把 4.1 节里桌面连接的参数换成：

| 目标系统 | Guacamole 协议 | 要在系统里打开 | 默认端口 |
|---|---|---|---|
| Windows | `rdp` | 设置 → 系统 → 远程桌面 | `3389` |
| macOS | `vnc` | 系统设置 → 通用 → 共享 → 屏幕共享 | `5900` |

还有三点要注意。Guacamole 的 RDP 参数里，`security` 默认是 `any`，会自动协商；`ignore-cert=true` 可以忽略自签证书；`console=true` 表示连到 console 会话，Windows 上建议先试这个。如果容器跑在 Docker Desktop 上，也就是 Mac 和 Windows 上常见的情形，容器访问宿主机要用 `host.docker.internal`，不是 `172.30.0.1`，4.1 节和 5.1 节的 `hostname` 都要改成它。4.3 节的 `xset` 是 X11 专有的，在这两套系统上无效，改成在系统设置里把关闭显示器的时间设为从不。

第 5 节的终端连接在这两套系统上同样未经验证。Windows 需要额外启用可选的 OpenSSH Server，macOS 在共享里的远程登录打开就有 sshd。

最后有两点必须实测，不能照本文直接下结论：Windows 的 RDP 是否真的接到本机正在使用的那个交互会话，从而满足看到同一块屏的要求；macOS 的屏幕共享在被远程连接时，本机屏幕会是什么表现。
