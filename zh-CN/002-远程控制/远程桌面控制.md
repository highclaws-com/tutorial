# 远程桌面控制

**用途**：让用户在普通浏览器里看到并操作目标机器的真实桌面。沙箱里已经运行一套公共的 Apache Guacamole，目标机器只负责暴露桌面协议。从建立隧道、安装桌面服务、创建连接、设置登录密码到交付网址，全部由 AI Agent 完成；用户只需要在自己的电脑上执行一条 `hc expose` 命令，最后打开一个网址。

**读者**：沙箱内的 AI Agent。命令可以直接复制执行。

**适用范围**：第 1 到 8 节的 Linux X11 路径经过验证。Windows 与 macOS 的差异集中在第 9 节，那一节未经验证。

## 0. 占位符

| 占位符 | 含义 |
|---|---|
| `<TUNNEL_HOST>` | 用户执行 `hc expose tcp:22` 后得到的隧道域名 |
| `<SSH_USER>` / `<SSH_PASSWORD>` | 目标机器的 SSH 账号与密码 |
| `<FWD_PORT>` | 沙箱内转发端口，避开已发布的 `8000-8080`，建议 9000 以上 |
| `<DESKTOP_PASSWORD>` | 桌面服务的密码，由 Agent 生成 |
| `<TARGET_NAME>` | Guacamole 里这条连接的名字 |
| `<GUAC_ADMIN_PASSWORD>` | Agent 为 Guacamole 登录面板生成的密码，绝不使用默认值 |
| `<SANDBOX_URL>` | 用户访问沙箱的网址，形如 `https://<沙箱域名>` |

## 1. 结构

```
用户电脑 ── hc expose tcp:22 ──> Cloudflare ──> sandbox_env
                                                   │  cloudflared access + ssh -L
                                                   ▼
                                             guacd ──> guacamole Web ──> 用户浏览器
```

- `guacd`（协议代理）常驻，负责真正去连 RDP/VNC。
- `guacamole`（Web 界面）是吃内存的部分，**默认关闭**，用户从控制台按需启动。
- 目标机器的桌面服务（RDP/VNC）安装、配置、保活都由 Agent 通过 SSH 完成。

## 2. 用户侧唯一的一步

让用户在他自己的电脑上执行：

```sh
hc expose tcp:22
```

它会打印一个 `xxxx.trycloudflare.com` 域名，记作 `<TUNNEL_HOST>`。同时向用户确认 `<SSH_USER>` / `<SSH_PASSWORD>`。隧道域名在重启后会变，届时重跑这条命令并更新沙箱里的配置。

## 3. Agent 在沙箱内建立通道

以下命令都在沙箱的 `sandbox_env` 里执行。先验证 SSH 通了：

```sh
sshpass -p "$SSH_PASSWORD" ssh \
  -o PubkeyAuthentication=no -o StrictHostKeyChecking=no \
  -p 2222 "$SSH_USER"@127.0.0.1 'uname -a'
```

`ssh` 之前需要先有一层把隧道桥到本地端口的进程；两层都用 Supervisor 保活（`autostart=true`、`autorestart=true`、`stopasgroup/killasgroup=true`）：

```sh
# 1) 把 Cloudflare 隧道桥到本地 2222
cloudflared access tcp --hostname "$TUNNEL_HOST" --url 127.0.0.1:2222

# 2) 把目标机器的桌面端口转发到 sandbox_env 的 <FWD_PORT>
#    Linux 用 5900（VNC），Windows 用 3389（RDP）
sshpass -p "$SSH_PASSWORD" ssh \
  -o PubkeyAuthentication=no -o StrictHostKeyChecking=no \
  -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -p 2222 -N -L 0.0.0.0:"$FWD_PORT":127.0.0.1:5900 "$SSH_USER"@127.0.0.1
```

`-L 0.0.0.0` 是必须的：guacd 在另一个容器里，只有绑到所有网卡才连得到 `sandbox_env:<FWD_PORT>`。端口不要落在 `8000-8080`。

## 4. 目标机器：Linux

Linux 要共享的是当前已经在用的那块物理桌面，必须用 VNC；RDP 会另起一个独立登录会话，看不到本机桌面。

这些操作由 Agent 通过上面那条 SSH 通道执行。先装 x11vnc 并生成密码：

```sh
sudo apt install -y x11vnc        # Arch: sudo pacman -Sy --noconfirm x11vnc
x11vnc -storepasswd "$DESKTOP_PASSWORD" ~/.vnc.pass
```

然后在**图形会话所属用户**下启动 x11vnc（不要用 root）。`-auth` 指向该会话的 X 授权文件：

```sh
AUTH=$(ls ~/.Xauthority /run/user/$UID/*/Xauthority /tmp/serverauth.* 2>/dev/null | head -1)

systemd-run --user --unit=x11vnc-guac /usr/bin/x11vnc \
  -display :0 -auth "$AUTH" \
  -rfbauth ~/.vnc.pass -rfbport 5900 -listen 127.0.0.1 \
  -no6 -noipv6 -forever -shared \
  -scale 1920x1080 -xdamage -wait 33 -defer 33
```

画面一律固定 1080p、每秒约 30 次，跟目标屏幕分辨率无关。绝大多数「太卡」都不是目标性能不足，而是对方网速不够：

| 参数 | 作用 |
|---|---|
| `-listen 127.0.0.1` | 只对本机开放，SSH 转发之外都连不到 |
| `-scale 1920x1080` | 固定 1080p 输出，是固定尺寸，不是 `1/2` 这种比例 |
| `-xdamage` | 只发变化区域，不要用 `-noxdamage` |
| `-wait 33 -defer 33` | 刷新压到约每秒 30 次 |

关掉熄屏，否则远程画面会变成全黑，容易被误判为故障：

```sh
export DISPLAY=:0
xset s off; xset s noblank; xset -dpms
```

## 5. Windows 与 macOS

两者都自带远程桌面服务，跳过第 4 节。下面的开关由 Agent 通过 SSH 打开。

| 目标系统 | Guacamole 协议 | 要打开 | 端口 |
|---|---|---|---|
| Windows | `rdp` | 「设置 → 系统 → 远程桌面」 | `3389` |
| macOS | `vnc` | 「系统设置 → 通用 → 共享 → 屏幕共享」 | `5900` |

Windows 上先试 `console=true` 连到 console 会话，并加 `ignore-cert=true`；`security` 默认 `any` 会自动协商。macOS 的屏幕共享本身就是 VNC 协议，需要设置 VNC 密码。

## 6. 启动 Guacamole、改密码、建连接

Guacamole 的 scoped 数据库和表结构由沙箱自动准备好。先启动它（默认关闭）：可以从沙箱控制台按「启动远程桌面」，Agent 也可以调管理器接口：

```sh
curl -X PUT http://sandbox_mgr:8000/api/v1/guacamole
```

Web 界面在 `http://guacamole:8080/guacamole/`，接口前缀 `/guacamole/api`，数据源固定为 `postgresql`，之后每个请求都带 `?token=<authToken>`。

### 6.1 用默认账号换一次令牌

新装好的 Guacamole 只有一个默认账号 `guacadmin / guacadmin`。**这个默认密码绝不能交给用户**，但先用它换一次令牌：

```sh
curl -s -X POST 'http://guacamole:8080/guacamole/api/tokens' \
  -d 'username=guacadmin&password=guacadmin'
```

### 6.2 立刻改成随机密码（交付前必须做）

生成一个强密码，记作 `<GUAC_ADMIN_PASSWORD>`：

```sh
python3 -c 'import secrets; print(secrets.token_urlsafe(16))'
```

用刚才的令牌替换默认密码：

```sh
curl -X PUT \
  'http://guacamole:8080/guacamole/api/session/data/postgresql/users/guacadmin/password?token=<authToken>' \
  -H 'Content-Type: application/json' \
  -d '{"oldPassword":"guacadmin","newPassword":"<GUAC_ADMIN_PASSWORD>"}'
```

改完后默认密码立即失效。用 `<GUAC_ADMIN_PASSWORD>` 重新取一次令牌，后面的请求都用新令牌；把 `<GUAC_ADMIN_PASSWORD>` 交给用户。

### 6.3 创建连接

用新令牌向 `POST /guacamole/api/session/data/postgresql/connections?token=<token>` 提交：

```json
{"parentIdentifier":"ROOT","name":"<TARGET_NAME>","protocol":"vnc",
 "parameters":{"hostname":"sandbox_env","port":"<FWD_PORT>","password":"<DESKTOP_PASSWORD>","color-depth":"16"},
 "attributes":{}}
```

Windows 把 `protocol` 改成 `rdp`，`password` 换成该机的登录密码。`hostname` 填 `sandbox_env`：guacd 在容器里运行，填 `localhost` 只会指到它自己。

## 7. 交付给用户

把登录步骤和凭据一起给用户，按顺序说清楚：

1. 在浏览器打开登录面板：`<SANDBOX_URL>/guacamole/`（例如 `https://<沙箱域名>/guacamole/`）。
2. 用用户名 `guacadmin`、密码 `<GUAC_ADMIN_PASSWORD>` 登录。
3. 点击连接 `<TARGET_NAME>`，浏览器里就会出现目标机器的真实桌面。

同时提醒两件事：画面就是目标机器的真机桌面，按机密对待；看完在控制台把「远程桌面」关掉可以释放内存，下次用之前再打开。

## 8. 验证与故障

- `ss -tlnp | grep <FWD_PORT>` 能在 `sandbox_env` 里看到转发端口
- 启动 Guacamole 后 `/guacamole/` 返回 200，默认密码登录失败、新密码可登录
- 连接列表里有指向 `sandbox_env:<FWD_PORT>` 的连接，从公网入口能看到并操作真实桌面

| 现象 | 原因 | 处理 |
|---|---|---|
| 入口 404 | 网址少了 `/guacamole/`，或服务没启动 | 补全路径；启动远程桌面 |
| 桌面全黑 | 桌面被熄屏 | 重做第 4 节的 `xset` |
| 桌面显示锁屏 | 桌面本来就锁着 | 要在目标机器上解锁，远程绕不过去 |
| 报 VNC 不可达 | x11vnc 没在跑，或 `-auth` 路径过期 | 重跑第 4 节；路径每次登录都会变 |
| 桌面卡、有黑块 | 缩放、刷新或色深设置丢了 | 核对 `-scale 1920x1080`、`-wait 33 -defer 33`、`color-depth=16` |
| ssh 连不上 | 隧道域名变了或进程挂了 | 让用户重跑 `hc expose tcp:22`，更新单位并重启 |
| 连不上桌面 | `<FWD_PORT>` 被占用或转发进程退出 | 换端口，重启转发进程 |

**重启后恢复**：`guacd` 与连接定义都会自己回来；需要重建的是第 3 节的两层通道（隧道域名可能已变）和重启后的 x11vnc。Guacamole Web 仍然默认关闭，由控制台按需启动。
